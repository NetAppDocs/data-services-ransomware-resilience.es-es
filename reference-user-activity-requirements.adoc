= Requisitos de detección de actividad de usuario para NetApp Ransomware Resilience
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
NetApp Ransomware Resilience te permite responder a eventos de ransomware a nivel de usuario con la detección del comportamiento del usuario. Debes crear un tenant y un conjunto de agentes para habilitar la detección del comportamiento del usuario. Antes de habilitar la detección, debes asegurarte de cumplir los requisitos indicados de sistema operativo, servidor y red para que Ransomware Resilience pueda detectar e informar correctamente de los eventos.



[[cloud-provider-support]]
== Soporte del proveedor de la nube

Para habilitar la detección del comportamiento de los usuarios, debes crear un entorno ejecutable para los recopiladores de datos, que comparten los eventos de actividad de los usuarios con Ransomware Resilience.


NOTE: La implementación regional del tenant no afecta al agente de NetApp Console. La implementación del agente de NetApp Console es independiente de estas regiones.

El tenant se puede implementar en AWS y Azure en las siguientes regiones:

|===
| Proveedor de nube | Región 


| AWS  a| 
* Asia Pacífico (Sídney) (ap-southeast-2)
* Europa (Frankfurt) (eu-central-1)
* Este de EE. UU. (Norte de Virginia) (us-east-1)




| Azur | Este de EE. UU. 
|===


[[operating-system-requirements]]
== Requisitos del sistema operativo

La detección de comportamiento sospechoso del usuario es compatible con los siguientes sistemas operativos:

[cols="2"]
|===
| Sistema operativo | Versiones compatibles 


| AlmaLinux | 9.4 (64 bits) a 9.5 (64 bits) y 10 (64 bits), incluido SELinux 


| CentOS | CentOS Stream 9 (64 bits) 


| Debian | 11 (64 bits), 12 (64 bits), incluido SELinux 


| OpenSUSE Leap | 15.3 (64 bits) a 15.6 (64 bits) 


| Oracle Linux | 8.10 (64 bits) y 9.1 (64 bits) a 9.6 (64 bits), incluido SELinux 


| Red Hat Enterprise Linux | 8.10 (64 bits), 9.1 (64 bits) a 9.6 (64 bits) y 10 (64 bits), incluido SELinux 


| Rocoso | De la versión 9.4 (64 bits) a la 9.6 (64 bits), incluido SELinux 


| SUSE Linux Enterprise Server | 15 SP4 (64 bits) a 15 SP6 (64 bits), incluido SELinux 


| Ubuntu | 20.04 LTS (64 bits), 22.04 LTS (64 bits) y 24.04 LTS (64 bits) 
|===

NOTE: La máquina que utilice para el agente de actividad del usuario no debe estar ejecutando otro software de nivel de aplicación. Se recomienda un servidor dedicado.

El comando  `unzip` es necesario para la instalación. El comando  `sudo su -` es necesario para la instalación, la ejecución de scripts y la desinstalación.



[[server-requirements]]
== Requisitos del servidor

El servidor debe cumplir los siguientes requisitos mínimos:

* **CPU**: 4 núcleos
* **RAM**: 16 GB de RAM
* **espacio en disco**: 36 GB libres




[[server-recommendations]]
=== Recomendaciones del servidor

* Asigna espacio adicional en disco para permitir la creación del sistema de archivos. Asegúrate de que haya al menos 35 GB de espacio libre en el sistema de archivos. + Si `/opt` es una carpeta montada desde un almacenamiento NAS, los usuarios locales deben tener acceso a dicha carpeta. La creación del agente de actividad de usuario puede fallar si los usuarios locales no disponen de los permisos necesarios.
* Instala el agente de actividad del usuario en un sistema independiente de tu entorno de Ransomware Resilience. Si instalas el agente y Ransomware Resilience en el mismo equipo, asegúrate de disponer de entre 50 y 55 GB de espacio en disco. En el caso de Linux, asigna entre 25 y 30 GB de espacio a `/opt/netapp` y 25 GB a `/var/log/netapp`.
* Se recomienda sincronizar la hora tanto en el sistema ONTAP como en la máquina del agente de actividad del usuario mediante el Protocolo de tiempo de red (NTP) o el Protocolo simple de tiempo de red (SNTP).




[[sizing-recommendations]]
=== Recomendaciones de dimensionamiento

Al recopilar eventos de usuario, asegúrate de que el equipo que aloja el agente de actividad de usuario tenga la capacidad suficiente para soportar tu tasa de eventos. Esto significa asegurarte de que dispones de suficientes recopiladores de datos y de suficiente CPU y RAM en el equipo que aloja el agente de actividad de usuario para gestionar el número de eventos por segundo. Para aumentar el número de recopiladores de datos, es posible que tengas que aumentar la capacidad de RAM o de CPU. Ransomware Resilience admite hasta 50 recopiladores de datos por agente de actividad de usuario.

La siguiente tabla proporciona una orientación general para el dimensionamiento:

|===
| Configuración de la máquina del agente de actividad del usuario | Número de recopiladores de datos | Índice máximo de eventos 


| 4 núcleos, 16GB | 10 recopiladores de datos | 20,000 eventos/segundo 


| 4 núcleos, 32GB | 20 recopiladores de datos | 20,000 eventos/segundo 
|===
También puedes calcular tus necesidades específicas. Al calcular el tamaño adecuado, se recomienda que utilices un porcentaje de búfer del 30%. Utiliza esta fórmula para determinar si tu configuración puede soportar la carga.

[listing]
----
Where E is the sum of all events per second across all data collectors:

E + (0.3 x E) < 20,000 events/second
----
.Calcula la tasa de datos de eventos en Ransomware Resilience.
[%collapsible]
====
Ransomware Resilience proporciona un script que puedes ejecutar en tu sistema para calcular la tasa de datos de eventos. De forma predeterminada, el script se ejecuta para un máximo de cinco SVM. Si tu entorno incluye más de cinco SVM, puedes modificar el script en consecuencia. Independientemente del número de SVM, el script tarda aproximadamente cinco minutos en obtener una lectura de la tasa media de eventos. Antes de ejecutar el script, debes tener:

* link:suspicious-user-activity.html["Configuraste un agente de actividad del usuario"]
* La dirección IP del clúster
* El nombre de usuario y la contraseña del administrador del clúster
* Instalado `sshpass` en el equipo con Linux (puedes instalarlo con el comando `sudo yum install -y sshpass`)


.Pasos
. Desde el equipo que aloja el agente de actividad del usuario, ejecuta el script como administrador: `/opt/netapp/cloudsecure/agent/install/svm_event_rate_checker.sh`
. Cuando se te solicite, introduce la dirección IP del clúster, el nombre de usuario admin y la contraseña admin.
. El script tarda aproximadamente cinco minutos en ejecutarse. Cuando finaliza, la línea de comandos muestra la tasa de eventos, por ejemplo "Svm svm_rate está generando 100 eventos/seg."
+
Utiliza el índice de eventos para calcular tu tamaño.



====


[[cloud-network-access-rules]]
== Reglas de acceso a la red en la nube

Revise las reglas de acceso a la red en la nube para su geografía relevante (Asia Pacífico, Europa o Estados Unidos).


IMPORTANT: Durante la instalación inicial, reemplaza el  `<site_name>` con un permiso comodín (`*`). Después de que el agente esté activado y completamente operativo, puedes reemplazar el permiso por el nombre del sitio. Contacta a tu representante de NetApp para el nombre del sitio.


NOTE: El agente de actividad del usuario utiliza la tecnología de NetApp Data Infrastructure Insights, de ahí el uso de endpoints de `cloudinsights`. Para obtener más información, consulta link:concept-user-behavior.html#user-activity-forensics["Ransomware Resilience y Data Infrastructure Insights"].

== Reglas dentro de la red

|===

| TCP | 389 (LDAP) 636 (LDAPS / StartTLS) | Agente de actividad del usuario | URL del servidor LDAP | Conectarse a LDAP 


| HTTPS (TCP) | 443 | Agente de actividad del usuario | Dirección IP de administración del clúster o SVM (según la configuración del recopilador SVM) | Comunicación API con ONTAP 


| TCP | 35000-55000  a| 
Direcciones IP de LIF de datos SVM
| Agente de actividad del usuario | Comunicación de ONTAP al agente de actividad del usuario para eventos de FPolicy. Estos puertos deben estar abiertos hacia el agente de actividad del usuario para que ONTAP pueda enviarle eventos, incluido cualquier cortafuegos del propio agente de actividad del usuario (si lo hay). + **NOTA:** no es necesario reservar *todos* estos puertos, pero los que reserves para este fin deben estar dentro de este rango. Se recomienda empezar reservando 100 puertos y aumentar el número si es necesario. 


| TCP | 35000-55000 | IP de gestión del clúster | agente de actividad del usuario | Comunicación desde la IP de gestión del clúster ONTAP al agente de actividad del usuario para *eventos EMS*. Estos puertos deben estar abiertos hacia el agente de actividad del usuario para que ONTAP pueda enviarle eventos EMS, incluido cualquier cortafuegos del propio agente de actividad del usuario. + **NOTA:** no es necesario reservar *todos* estos puertos, pero los que se reserven para este fin deben estar dentro de este rango. Se recomienda empezar reservando 100 puertos y aumentar el número si es necesario. 


| SSH | 22 | Agente de actividad del usuario | Gestión de clústeres | Necesario para el bloqueo de usuarios CIFS/SMB. 
|===
